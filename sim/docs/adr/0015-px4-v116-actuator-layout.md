# ADR 0015: PX4 v1.16.2 packs HIL_ACTUATOR_CONTROLS with size-sorted core fields

**Status**: Accepted (2026-09-07, completes the "crate fix pending review" noted in ADR-0011r)
**Context**: Physical flight (I-2) requires decoding PX4 v1.16.2's HIL_ACTUATOR_CONTROLS(93)
exactly as it is sent. During live bring-up the sim decoded rotors stopped at 0.0 while PX4
logged "Takeoff detected"; a wire sniffer (`scripts/wire_sniff.py`, prior session) and a
replay of the failed run showed motor bytes landing in decoded slots 2..5 and the armed bit
never set — an 8-byte offset error. The I-2 harness temporarily worked around this with
`tests/i2_wire_proxy.py` re-laying-out msg 93 between PX4 and the sim.

**Evidence**: PX4 v1.16.2's bundled dialect (mirrored in the generated
`build/px4_sitl_default/mavlink/common/mavlink_msg_hil_actuator_controls.h`) packs the
message with size-sorted core fields:

```
time_usec: u64   @ 0
flags:     u64   @ 8
controls:  f32[16] @ 16..80   (motors 0..3 at 16..32)
mode:      u8    @ 80         (0x01 | 0x80 when armed)
```

The current official common.xml instead treats `flags` as a trailing extension field
(controls @ 8, mode @ 72, flags @ 73), which is also what pymavlink 2.4.49 encodes. Both
dialects share LEN=81 and CRC_EXTRA=47, so frames pass CRC either way — only the field
offsets differ, and only PX4->sim traffic is affected (the sim->PX4 direction was verified
byte-correct against PX4's own decoder).

**Decision**: `sitsim-mavlink` decodes (and encodes) msg 93 in the PX4 v1.16.2 layout. The
module's stated rule — "the generated PX4 headers and live wire behavior are the authority"
— now holds for all six messages. The golden vector is regenerated by
`scripts/gen_golden93.py`; `codec.rs` pins the offsets and adds a live-capture-style armed
frame regression. The I-2 harness runs DIRECT (PX4 -> sim on 4560) again; the wire proxy
remains available as a generic wire debugger, not a required component.

**Consequences**:
- F-2 (mavfleet driving rustsitsim per vehicle, no proxy) is unblocked — each vehicle's
  sitsim listens on 4560+i and PX4 connects straight to it.
- Frames encoded by pymavlink/newer official dialects for msg 93 would mis-decode; that is
  acceptable (this simulator targets real PX4 SITL, and the divergence is documented).
- ADR-0011r's value scale (per-motor [0,1] normalized thrust, armed = mode & 0x80) is
  unchanged; only the byte offsets moved.
