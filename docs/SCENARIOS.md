# mavfleet Scenario DSL Reference

A fleet scenario is one TOML file: fleet parameters, per-vehicle overrides, the
geofence, the task set, the timeline (faults and link events), and success criteria.
Per-vehicle rustsitsim configs are generated by the manager from defaults plus
overrides, so a scenario never repeats 60 lines of sensor parameters per vehicle
unless it wants to.

Unknown keys are **rejected**, not ignored — a scenario that quietly drops a typo'd
key is a test hazard. `mavfleet check <file>` validates without running.

## Schema (spec §9.1)

| Key | Type | Default | Meaning |
|---|---|---|---|
| `[fleet] count` | u8 | 2 | Vehicles to spawn (1-8) |
| `[fleet] battery_sim` | bool | true | Per-vehicle battery discharge (the safety ladder needs it) |
| `[fleet] restart_on_fault` | bool | false | Auto-restart FAULT vehicles |
| `[fleet] tick_hz` | u8 | 10 | Supervisor rate (fixed at 10 in v0.1; key reserved) |
| `[env] geofence.points_ned_m` | [[f32;2]] | 100 m square | Inclusion polygon vertices |
| `[env] geofence.ceiling_m`, `floor_m` | f32 | 60, 0 | Altitude box (NED z: -ceiling..-floor) |
| `[env] wind_steady_ms`, `turbulence` | [f32;3], enum | 0, "moderate" | Passed to every vehicle's simulator config |
| `[[tasks]]` | array | - | Task list: `id`, `pos_ned_m`, `hover_s`, `reward`, `deadline_s` |
| `[[vehicle_override]]` | array | - | `index` + partial rustsitsim config patch (e.g. battery) |
| `[[event]]` | array | - | Timeline: `fault` (proxied to a vehicle's sim), `link_loss` (vehicle + duration), `estop` (fleet-wide) |
| `[success]` | table | - | Criteria (below) |
| `[sim] command`, `duration_s` | string, f64 | prototype, 300 | Per-vehicle simulator command template (ADR-0008) |

Positions are NED metres, home-relative (z negative up). Tasks are waypoint visits in
v0.1; a task is rejected at compile time if no vehicle can reach it, with a logged
reason — not discovered mid-flight.

## Success criteria (spec §9.2)

| Key | Type | Meaning |
|---|---|---|
| `all_tasks_done` | bool | Every task completed (telemetry-observed or profile deadline) |
| `all_landed` | bool | Every vehicle ended landed |
| `max_time_s` | f64 | Wall-clock fleet time bound |
| `no_geofence_breach` | bool | No vehicle exited the fence during the run |
| `fsm_trace` | array | Ordered arc assertions: `{vehicle, from, to, cause}` |

Criteria are pure predicates over the run report's own data, evaluated by the same
code path in CI and in the dashboard's run review — what CI asserts is exactly what
the operator sees. The run report (JSON + event log) is written at run end regardless
of outcome: fleet summary, per-vehicle FSM trace, task completion table, supervisor
actions, criterion evaluation.

## Canonical example (Appendix B)

`docs/examples/fleet-basic.toml` — the F-2/F-3 driver. 2 vehicles, 4 tasks, one link
loss (expect heartbeat-loss → RTL on vehicle 1), one GPS denial (vehicle 0), battery
ladder accelerated on vehicle 1:

```toml
[fleet]
count = 2
battery_sim = true
restart_on_fault = false

[env]
geofence = { points_ned_m = [[-100,-100],[100,-100],[100,100],[-100,100]], ceiling_m = 60, floor_m = 0 }
wind_steady_ms = [1.0, 0.0, 0.0]
turbulence = "light"

[[tasks]]
id = "wp_n"
pos_ned_m = [-60.0, 0.0, -12.0]
hover_s = 5

# ... wp_e, wp_s, wp_w ...

[[vehicle_override]]
index = 1
battery = { discharge_scale = 1.6 }   # accelerates the ladder test path

[[event]]
kind = "link_loss"
vehicle = 1
start_s = 40
duration_s = 15

[[event]]
kind = "fault"
vehicle = 0
fault = { type = "gps_denial", start_ms = 30000, duration_ms = 20000 }

[success]
all_tasks_done = true
all_landed = true
max_time_s = 300
no_geofence_breach = true
fsm_trace = [
  { vehicle = 1, from = "ACTIVE", to = "RTL", cause = "heartbeat_loss" }
]
```

## Event kinds

| kind | Required fields | Effect |
|---|---|---|
| `link_loss` | `vehicle`, `start_s`, `duration_s` | Drop the manager's heartbeat reception for vehicle i for the window — the §8 heartbeat-loss ladder must fire |
| `fault` | `vehicle`, `fault = { type, start_ms, duration_ms }` | Proxied to vehicle i's simulator fault plane (rustsitsim fault catalog: `gps_denial`, `gps_glitch`, `gyro_bias`, `accel_bias`, `baro_drift`, `mag_disturbance`, `motor_loss`, `wind_gust`, ...) |
| `estop` | (none; fleet-wide) | Every vehicle lands immediately, scenario marked ABORTED |

`estop` is fleet-wide: per-vehicle `estop` events are a schema error.

## Determinism (spec §10.2)

The manager is deterministic in its **decisions** (bid function, auction order, policy
order) and nondeterministic in **timing** (real processes, real network). Timeline
events fire on the supervisor's fleet clock, so causal order of injected events is
stable across runs. CI assertions target event ordering and report data, never
timestamps.
